# Отчет о дебагинге и исправлениях

## Проблема

При запуске сервиса возникали следующие проблемы:

1. **TLS ошибка**: TLS включен, но файлы сертификатов отсутствуют (`/path/to/client.crt`, `/path/to/client.key`)
2. **Цикл переподключений**: После автоматического отключения TLS и обновления конфигурации срабатывало уведомление, которое вызывало повторное переподключение
3. **Ошибка подключения**: `getaddrinfo failed` для хоста `new-broker` (нормально, если брокер недоступен)

## Исправления

### 1. Гибкая обработка TLS (app/services/mqtt_client_service.py)

**Проблема**: При включенном TLS и отсутствующих файлах сертификатов сервис выбрасывал исключение и не мог подключиться.

**Решение**:
- Добавлена проверка переменной окружения `MQTT_TLS_REQUIRED`
- Если `MQTT_TLS_REQUIRED=false` (по умолчанию) и файлы отсутствуют → TLS отключается с предупреждением, сервис продолжает работу без TLS
- Если `MQTT_TLS_REQUIRED=true` → выбрасывается исключение (TLS обязателен)

**Код**:
```python
if missing_files:
    if tls_required:
        raise RuntimeError(f"TLS required but configuration invalid: {error_msg}")
    else:
        self._log_error(f"[{self.component_name}] {error_msg} Disabling TLS and continuing without encryption.")
        tls_was_disabled = True
```

### 2. Автоматическое переключение порта при отключении TLS

**Проблема**: После отключения TLS клиент все еще пытался подключиться к TLS-порту (8883).

**Решение**:
- При отключении TLS автоматически переключается порт с 8883 на 1883
- Конфигурация обновляется в `ConfigService` для сохранения изменений

**Код**:
```python
if tls_was_disabled and client_config.use_tls:
    if client_config.port == 8883:  # TLS port
        client_config.port = MQTT_DEFAULT_PORT
        client_config.use_tls = False
        # Update config in ConfigService
        self.config_service.update_config({
            "MQTT_USE_TLS": "false",
            "MQTT_PORT": str(MQTT_DEFAULT_PORT),
        }, ...)
```

### 3. Предотвращение цикла переподключений

**Проблема**: При обновлении конфигурации срабатывало уведомление, которое вызывало повторное переподключение, создавая цикл.

**Решение**:
- Добавлен флаг `_ignore_config_changes` для игнорирования уведомлений об изменениях, которые мы сами инициировали
- Перед обновлением конфигурации устанавливается флаг, после обновления (с небольшой задержкой) флаг сбрасывается

**Код**:
```python
# Set flag to ignore config change notification we're about to trigger
self._ignore_config_changes.set()
try:
    self.config_service.update_config(...)
finally:
    # Clear flag after a short delay
    threading.Thread(target=lambda: (time.sleep(0.1), self._ignore_config_changes.clear()), daemon=True).start()
```

И в `_on_config_changed`:
```python
if self._ignore_config_changes.is_set():
    self._log_info(f"[{self.component_name}] Ignoring config change (initiated by self): {notification.event.value}")
    return
```

## Текущее поведение

1. ✅ TLS отключается автоматически при отсутствии файлов сертификатов (если `MQTT_TLS_REQUIRED=false`)
2. ✅ Порт автоматически переключается с 8883 на 1883
3. ✅ Конфигурация сохраняется в БД
4. ✅ Нет цикла переподключений при автоматическом обновлении конфигурации
5. ✅ Клиент пытается подключиться к брокеру (ошибка `getaddrinfo failed` нормальна, если брокер недоступен)

## Ожидаемое поведение при недоступном брокере

Если брокер недоступен (например, `new-broker`), сервис будет:
- Пытаться подключиться с exponential backoff
- Логировать ошибки подключения (с throttling, чтобы не спамить)
- Продолжать попытки переподключения до успешного подключения или остановки сервиса

Это нормальное поведение для MQTT клиента.

## Рекомендации

1. **Для тестирования**: Используйте доступный MQTT брокер (например, `localhost` или реальный IP)
2. **Для production**: Убедитесь, что брокер доступен и конфигурация корректна
3. **Для TLS**: Либо отключите TLS, либо укажите правильные пути к сертификатам

## Тестирование

Для проверки работы сервиса:

1. **Проверка TLS отключения**:
   ```bash
   python main.py
   # Должно отключить TLS автоматически и переключить порт на 1883
   ```

2. **Проверка с доступным брокером**:
   - Установите правильный адрес брокера в конфигурации
   - Сервис должен подключиться успешно

3. **Проверка переподключения**:
   - Запустите сервис
   - Временно отключите брокер
   - Включите брокер обратно
   - Сервис должен автоматически переподключиться
