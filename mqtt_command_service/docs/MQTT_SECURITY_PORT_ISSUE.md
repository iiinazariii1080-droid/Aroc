# Проблема безопасности: команды принимаются через незащищенный порт

## Проблема

**Ситуация:**
- Сервис (bridge) подключен к брокеру на порту **8883** с TLS (защищенное соединение)
- Команда отправлена через `mosquitto_pub` на порт **1883** без TLS (незащищенное соединение)
- Команда **успешно отработала**

**Вопрос:** Почему команда отработала, если сервис настроен на порт 8883?

## Объяснение

### Как работает MQTT брокер (Mosquitto)

MQTT брокер может слушать на **нескольких портах одновременно**:

```
┌─────────────────────────────────────────┐
│         MQTT Broker (Mosquitto)         │
│                                         │
│  Port 1883 (MQTT, без TLS)              │
│  ├─ Принимает подключения               │
│  └─ Доставляет сообщения в топики       │
│                                         │
│  Port 8883 (MQTTS, с TLS)               │
│  ├─ Принимает подключения               │
│  └─ Доставляет сообщения в топики      │
│                                         │
│  ┌─────────────────────────────────┐   │
│  │     Общее хранилище топиков     │   │
│  │  aroc/robot/.../cmd/igus       │   │
│  │  aroc/robot/.../telemetry      │   │
│  └─────────────────────────────────┘   │
└─────────────────────────────────────────┘
         ▲                    ▲
         │                    │
    Port 1883           Port 8883
  (без TLS)            (с TLS)
         │                    │
    mosquitto_pub        Bridge Service
```

### Почему команда отработала

1. **Вы отправили команду** через `mosquitto_pub` на порт 1883 (без TLS)
2. **Брокер принял сообщение** и поместил его в топик `aroc/robot/fahrdummy-01/cmd/igus`
3. **Bridge подписан на этот топик** через порт 8883 (с TLS)
4. **Брокер доставил сообщение** всем подписчикам топика, независимо от того, через какой порт они подключены
5. **Bridge получил и обработал команду**

**Вывод:** Это работает, потому что брокер использует **общее хранилище топиков** для всех подключений, независимо от порта.

## Проблема безопасности

### ⚠️ Это проблема безопасности!

**Риски:**
1. **Перехват команд** - злоумышленник может отправить команды через незащищенный порт 1883
2. **Man-in-the-Middle атаки** - данные передаются в открытом виде
3. **Отсутствие шифрования** - пароли и команды видны в открытом виде
4. **Нарушение политики безопасности** - если сервис настроен на TLS, все соединения должны быть защищены

### ✅ Правильное поведение

**Все команды должны идти только через защищенный порт 8883 (TLS).**

## Решения

### Решение 1: Отключить порт 1883 на брокере (рекомендуется)

Настройте Mosquitto брокер, чтобы он **не слушал** на порту 1883:

**Файл конфигурации Mosquitto (`/etc/mosquitto/mosquitto.conf`):**

```conf
# Отключить обычный MQTT порт (1883)
# listener 1883  # Закомментировать или удалить

# Оставить только TLS порт (8883)
listener 8883
cafile /etc/mosquitto/certs/ca.crt
certfile /etc/mosquitto/certs/server.crt
keyfile /etc/mosquitto/certs/server.key
require_certificate false  # или true для mutual TLS
```

**После изменения конфигурации:**
```bash
sudo systemctl restart mosquitto
```

**Проверка:**
```bash
# Должно вернуть ошибку подключения
mosquitto_pub -h your-broker-ip -p 1883 -u bridge_user -P 'password' -t "test" -m "test"

# Должно работать
mosquitto_pub -h your-broker-ip -p 8883 --cafile /path/to/ca.crt -u bridge_user -P 'password' -t "test" -m "test"
```

---

### Решение 2: Использовать ACL для ограничения доступа на порту 1883

Настройте Access Control List (ACL), чтобы порт 1883 принимал только определенные топики (не команды):

**Файл ACL (`/etc/mosquitto/acl.conf`):**

```conf
# Пользователь bridge_user может публиковать только в телеметрию на порту 1883
user bridge_user
topic readwrite aroc/robot/+/telemetry
topic readwrite aroc/robot/+/status/+
# НЕ разрешать команды на порту 1883
```

**Файл конфигурации (`/etc/mosquitto/mosquitto.conf`):**

```conf
# Порт 1883 - только для чтения телеметрии
listener 1883
acl_file /etc/mosquitto/acl.conf

# Порт 8883 - полный доступ с TLS
listener 8883
cafile /etc/mosquitto/certs/ca.crt
certfile /etc/mosquitto/certs/server.crt
keyfile /etc/mosquitto/certs/server.key
```

---

### Решение 3: Использовать разные пользователи для разных портов

Создайте отдельного пользователя для незащищенного порта с ограниченными правами:

**Файл паролей (`/etc/mosquitto/passwd`):**

```
telemetry_user:$7$...
bridge_user:$7$...
```

**ACL:**

```conf
# Пользователь для порта 1883 - только телеметрия
user telemetry_user
topic readwrite aroc/robot/+/telemetry
topic read aroc/robot/+/status/+

# Пользователь для порта 8883 - полный доступ
user bridge_user
topic readwrite #
```

---

### Решение 4: Firewall правила (дополнительная защита)

Ограничьте доступ к порту 1883 через firewall:

```bash
# Разрешить доступ к порту 1883 только с определенных IP
sudo ufw allow from 192.168.1.0/24 to any port 1883

# Или полностью закрыть порт 1883
sudo ufw deny 1883
```

## Рекомендация

**Для production окружения:**

2. ✅ **Использовать только порт 8883 с TLS**
3. ✅ **Настроить firewall** для дополнительной защиты
4. ✅ **Использовать mutual TLS** (client certificates) для критичных команд

## Проверка текущей конфигурации

### Проверить, на каких портах слушает брокер:

```bash
# На сервере с брокером
sudo netstat -tlnp | grep mosquitto
# или
sudo ss -tlnp | grep mosquitto
```

**Ожидаемый вывод (если порт 1883 отключен):**
```
tcp  0  0  0.0.0.0:8883  0.0.0.0:*  LISTEN  1234/mosquitto
```

**Проблемный вывод (если порт 1883 включен):**
```
tcp  0  0  0.0.0.0:1883  0.0.0.0:*  LISTEN  1234/mosquitto
tcp  0  0  0.0.0.0:8883  0.0.0.0:*  LISTEN  1234/mosquitto
```

### Проверить конфигурацию Mosquitto:

```bash
# На сервере с брокером
sudo mosquitto -c /etc/mosquitto/mosquitto.conf -v
```

Это покажет все listener'ы и их настройки.
